**Scope:** initial targeted inventory, **not yet an exhaustive repository-wide audit**. All retirement entries below remain **OPEN** until change-specific adversarial and regression evidence is collected.

## Architectural criterion

KYO constitutes the sovereign hypergraph. Admission alone qualifies a particular traversal. BADGE certifies that qualification. EPoP proves that the certificate is exercised by the bound key holder. ICE is the complete-mediation boundary for execution. A catalog, credential, identity label, role, network connection, endpoint registration, backend protocol, or local capability enumeration must never independently grant execution authority.

An operational guard that can only *restrict* operations (schema validation, bounded computation, resource safety, cryptographic integrity or local refusal) is not automatically a competing sovereign authority. Preserve such guards unless a clear replacement is established.

**Lifecycle:** `IDENTIFIED` → `REPLACEMENT IMPLEMENTED` → `SHADOW PATH DISABLED` → `NEGATIVE TEST GREEN` → `RETIRED`. Record transition and evidence at the same time as each refactoring change; no retrospective blanket approval.

## Change notification and evidence log

Each code review/commit touching the authority plane must record one line **at the time of change**:

`YYYY-MM-DD | iteration | AR-ID | old code path → new path | former authority removed | evidence/test IDs + result | status transition | commit`.

Do not set `RETIRED` merely because a named literal disappears, a unit test passes, or a call is routed through the Hub. Retirement means (1) no remaining independent ALLOW path, (2) fail-closed denial by ICE or admission as applicable, (3) positive integration preserved, (4) an adversarial counterexample to the old path fails, and (5) any duplicate path/tombstone is audited.

## Proposed iteration order

1. **I1** — BADGE derived from verified admission evidence, exact traversal and holder key; address AR-08/09/12/13 compatibility without introducing new independent authority.
2. **I2** — ICE at operational Flower fit and inference boundaries; address AR-01–05 and AR-13; require EP01 and EP02 GREEN plus allowed A+B paths.
3. **I3** — Generalize admitted relations across human/agent, multiple agents, and Mode 1A guests; address AR-06/07/08/10/11.
4. **Closure** — whole-repository authority-path scan including deployment/proxy endpoints, ICE01–ICE03 adversarial complete-mediation matrix, tombstone checks and revalidation of every AR retirement.

The ordering is deliberately incremental across planes. Each iteration leaves a tested end-to-end slice; the register is not a mandate to perform all deletions first.
